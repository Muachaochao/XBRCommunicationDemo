# Avalonia 迁移验收标准

## 目标和边界

以 E:\HslCommunicationDemo-v13.0.3 中固定 SHA-256 的发布包为唯一行为基线。
新应用采用 Avalonia → MVVM → 通信服务 → HSL 协议适配层。
“一样”指完整功能和对外可观察行为一致，UI 按新风格重做，不要求像素一致。
反编译不能恢复原始注释或证明原始源码逐字一致；源码导出成功不等于可编译，也不等于迁移完成。
保留原有授权与功能限制，不将绕过授权作为迁移目标。

## 分阶段门槛

| 阶段 | 通过条件 | 必须保存的证据 |
|---|---|---|
| A 原版留档 | 全部输入文件记录大小和 SHA-256，原目录保持不变 | original-manifest.json；结束时重新核对哈希 |
| B 静态恢复 | 主程序、通信库、控件及升级程序导出；资源、类型、依赖有记录；所有反编译错误显式登记 | reverse 目录、导出命令、错误日志、迁移清单 |
| C 可构建 | 干净环境可复现 restore/build，0 编译错误；有独立可启动的恢复版程序 | 构建日志、运行截图、工具与依赖版本 |
| D 功能对照 | 每个原版菜单、页面、子标签和操作均映射到新实现；每项有用例及结果 | migration-inventory.csv，逐项补充动态操作清单 |
| E 通信一致 | 同样配置、初始设备状态及操作顺序下，请求语义、返回值、错误码一致 | 新旧报文、输入、预期值、实际值、设备/模拟器版本 |
| F 发布 | 全部范围内用例通过，无阻断/严重缺陷，无未说明的缺失功能 | 发布包、验收矩阵、已知差异和结果报告 |

静态清单只是入口候选，不能证明全部功能覆盖。须从原版主菜单与实际操作补齐；不能用清单行数充当完成率。

## 每个协议必须覆盖

1. 连接参数、默认值、合法/非法输入、连接成功、失败、超时、重复连接、断开再连接。
2. 原版支持的数据类型及标量/数组读写，最小/最大值、符号、浮点、字符串编码/长度、字节序。
3. 原版支持的地址表达式、站号、批量长度及分包边界。
4. 普通读写、批量读、原始报文、数据表、曲线、导出、模拟及协议特有功能，按原版实际存在的项目逐项验收。
5. 轮询启停、读写并发、网络中断恢复、关闭页面/程序的连接释放。不得向其他连接串发数据。
6. 原版配置加载、保存、重新打开后语义一致；升级前后都保留原文件备份，不用新格式覆盖唯一旧配置。
7. 成功结果、错误码、关键提示及按钮可用状态一致。UI 文案或流程改善必须记录为显式差异。

报文对比只允许归一化事先列明的事务 ID、时间戳等动态字段；地址、站号、功能码、数据载荷不能忽略。
写入对比必须在模拟器或明确的测试设备执行，新旧程序各自恢复相同初始状态后测试。

## 首个协议：Modbus TCP

已从 FormModbus.cs 确认须覆盖：Station、AddressStartWithZero、DataFormat 四种顺序、
IsStringReverse、IsCheckMessageId、StationCheckMatch、DisableFunctionCode06、BroadcastStation、
WordReadBatchLength、PipeSelectControl 传输设置、连接/断开、普通和批量读写、原始报文、
Modbus 特殊功能、站号搜索、地址示例、代码示例及保存/恢复。
其余通用子标签以 UserControlReadWriteDevice 的实际行为为准，不能只实现以上参数。

## 可用性与稳定性

- Windows 100%、125%、150%、200% 缩放无关键控件截断，主要操作有键盘焦点与明确状态。
- 每次更新后连接参数不丢失，关闭页面后无该页面产生的新轮询请求。
- 首批建议测试工况：10 个模拟连接、每连接 20 个点位、500ms 轮询，连续运行 8 小时。
- 同机同工况记录 CPU、私有内存、句柄、吞吐与请求延迟 P50/P95；测试前记录硬件及日志级别。
- UI 操作响应目标 P95 ≤ 200ms（不含设备网络等待），无未处理异常、死锁或持续资源增长。
- 模拟器通过只证明该场景通过；无真实设备的协议标记“待设备验收”，不能计为全部通过。
